# 交互设计与项目目录规划

版本：v0.2；日期：2026-10-28。以下目录是未来开发时的建议结构，本次仅创建文档。

## 1. 信息架构

| 一级页面 | 主要区域 | 用户动作 |
| --- | --- | --- |
| 总览 | 最近研究项目、创作任务、数据源健康度、待审核 | 继续工作、处理异常 |
| 选书研究 | 图书筛选、商品/账号/视频三类视图、证据详情 | 收藏、比较、创建风格卡片 |
| 图书库 | 版本信息、事实材料、商品映射、素材权利 | 校对事实、上传授权素材 |
| 风格库 | 风格卡片列表、特征和引用证据 | 编辑标签、组合风格 |
| 视频创作 | Brief 表单、拟挂商品、脚本版本、分镜时间轴、预览 | 生成、改稿、本人确认、渲染 |
| 发布包 | MP4、标题、简介、封面文案、商品核对卡 | 下载后在抖音/快手客户端发布并挂车 |
| 任务/审核 | 任务阶段、费用、待审核项、失败信息 | 审核、驳回、重试、取消 |
| 设置 | 成员、数据连接、模型/供应商、预算 | 管理授权与权限 |

## 2. 关键交互

**研究页**：默认先展示数据覆盖说明，再展示筛选器和结果。结果卡片固定显示「数据来源、时间窗、更新时间、实际/估算/热度标签」。点击数值可打开证据抽屉。跨平台切换时保留过滤条件，但不把不同口径指标画成同一条未经说明的曲线。

**创作页**：左侧是图书事实、拟挂商品、目标人群、平台和原创观点；中间是可编辑脚本与分镜；右侧是参考风格与证据。脚本中的事实性句子显示来源徽标；缺失来源时需要人工补证或改写。本人确认后冻结该版本，修改形成下一版。成片预览页显示版本、素材来源和渲染参数。默认模板只有文字动效和自制图形；未确认授权的书封、内页、商品图不能选入素材栏。

**发布包页**：按抖音/快手分别展示标题与简介建议、MP4 下载、拟挂商品 ID/链接、书籍版本核对项和平台内挂车步骤。用户勾选「账号可带货、商品可推广、视频主推商品一致」后，才把本地状态标记为可发布；系统不声称已替用户完成平台挂车。

**任务反馈**：进度按「准备 → 脚本 → 检查 → 待审核 → 分镜 → 渲染 → 完成」展示。外部 API 失败呈现可读原因（授权到期、配额不足、素材失效等），允许从失败阶段重试。前端用状态查询/SSE 更新，不以单个 HTTP 请求等待视频完成。

## 4. 目录边界

- `domain/` 不依赖某个平台接口格式；连接器先映射到统一契约。
- `workflows/` 只引用领域服务和媒体适配接口，不直接操作前端或平台 SDK。
- `media/` 将脚本/分镜转换为渲染清单，先用自制文字/图形；TTS 和后续第三方生成服务必须经过商用许可核验。
- `contracts/` 由后端 OpenAPI 与事件定义生成前端类型，避免两侧手写重复模型。
- 不为每个功能提前拆微服务；先用模块化单体加独立 worker，确认流量和团队边界后再拆分。
