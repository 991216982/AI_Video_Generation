```mermaid
flowchart LR
```

每个 `G` 由集成负责人独占 `packages/contracts/`、根配置、`main.py`、`worker.py`、`integration.py`、`infra/`、`.github/` 与端到端测试，先更新 OpenAPI/事件/样例并通知 A/B/C，再放行并行任务。每个 `W` 同时最多分给 A（领域/API）、B（前端）、C（生成链）三条工作流。三者共享目录时**不各自提交 Git**；若你用三个独立 Codex 工作树，则各自保留分支，集成负责人按 A → C → B 的依赖顺序合并。所有 Agent 遵守仓库根目录 `AGENTS.md` 的路径归属和素材边界。

按当前条件，建议先完成 W2、W3 和本人真实试用，再决定研究能力的投入深度。W4 可先做人工证据与风格卡；任何抖音/快手广域搜索、竞品销量和自动挂车都必须等到权限/合同证据明确后单独立项。

排期只作资源估算：G1/G2 各约 0.5–1 天；W2 约 3–5 天；W3 约 5–8 天；本人真实试用约 1–3 天；W4 约 4–6 天；W5 约 5–8 天；W6 按授权和反馈另估。每一波的三个 Agent 并行工作，但集成与修复要另留时间；外部账号/许可等待不计入这些数字。

## 6. W6：有条件的数据接口、复盘与后续扩展

W6 仅在 W5 稳定后立项，按需求和权利拆成独立任务，不能一口气交给同一轮 Agent：

1. **合法数据源试点**：先取得平台授权或第三方合同，列出字段、用途、时效、保留期限、费用和撤销处理，再由 A 实现一个连接器、B 增加来源展示、C 仅消费标准化证据。无授权时保持人工研究模式。
2. **效果复盘**：先让创作者手工录入发布链接与表现，记录平台、发布时间、视频/脚本版本；有自有账号授权后再评估回传。不要把播放量等同于图书销量。
3. **生成质量优化**：根据封测数据调整脚本/节奏/模板，建立 10–20 条有授权的评测 Brief；比较事实准确、原创性、人工改稿量、完成时间与成本。
4. **自动发布/挂车**：单独进行权限与产品可行性审查；当前不在开发承诺内。快手接口或抖音能力是否适用于具体账号和商品须以实际申请结果确认。

## 9. 人工输入与外部依赖

你需要提供或亲自核实：实际试点图书与平台商品 ID、账号的图书带货资格、书籍事实来源、你的原创荐书观点、自录音或 TTS 商用许可、后续预发部署预算/地区。没有这些输入时，Agent 可以使用标记为虚构的样例继续软件开发，但不能宣称真实带货流程已验收。
